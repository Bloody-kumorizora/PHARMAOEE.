# PharmaOEE 9.0.0

Учебное настольное приложение на Python для мониторинга **OEE** (Overall Equipment Effectiveness — общая
эффективность оборудования), учёта производственных показателей и анализа простоев на примере
фармацевтического производства. Интерфейс — на русском языке.

> **Учебный прототип.** PharmaOEE не является промышленной системой, не валидирован для GMP и не заявляет
> соответствия 21 CFR Part 11. В программе нет разграничения прав, электронных подписей и защищённого аудиторского
> следа. Подключения к реальному оборудованию (PLC, SCADA, MES, OPC UA) нет — источники событий только
> демонстрационные. Не используйте результаты как официальную производственную документацию.

## Возможности

| Раздел | Что можно сделать |
|---|---|
| **Главная панель** | OEE, доступность, производительность, качество; плановое время, время работы, простои, выпуск, годные, брак; динамика OEE по дням; главные причины простоев; список «Требует внимания» |
| **Производство** | Записи смен: добавление, изменение, удаление; предпросмотр OEE до сохранения; кнопка «Из простоев» (время работы = план − простои); защита от дубликатов; поиск и сортировка |
| **Оборудование** | Справочник линий: участок, идеальный цикл по умолчанию, статус «используется»; OEE и простои за период |
| **Простои** | Регистрация с датой и временем начала/окончания, переход через полночь, незавершённые простои, классификация по причинам, редактируемый справочник причин, сводки по причинам и оборудованию |
| **Аналитика и отчёты** | Динамика OEE и составляющих, Парето причин, рейтинг оборудования, сравнение смен, выпуск и брак, проблемные смены, повторяющиеся проблемы, автоматическая проверка данных, экспорт CSV |
| **Демо и симулятор** | Воспроизводимый генератор демо-данных за период (до 366 дней), симулятор смены с остановками и потерей связи, ручные сигналы-кнопки, безопасное удаление только сгенерированных данных |
| **Резервные копии** | Копия базы через backup API SQLite, проверка файла, восстановление с автоматической копией текущей базы, список копий |
| **Настройки и справка** | Порог OEE, данные по умолчанию, формулы и правила, ограничения, журнал изменений |

Общий фильтр сверху (период, оборудование, смена, происхождение данных) действует сразу на показатели, графики,
таблицы и экспорт. Обе границы периода включаются. Горячие клавиши: `Ctrl+1` … `Ctrl+8` — разделы, `F5` — обновить.

## Формулы OEE

| Показатель | Формула |
|---|---|
| Доступность (Availability) | время работы / плановое время |
| Производительность (Performance) | произведено × идеальный цикл / время работы |
| Качество (Quality) | годные / произведено |
| **OEE** | Доступность × Производительность × Качество = годные × идеальный цикл / плановое время |

Правила (подробно — в разделе «Настройки и справка» и в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)):

- Значения **не обрезаются до 100%**. Производительность выше 100% показывается с предупреждением: проверьте
  идеальный цикл, состав продукции и исходные данные.
- Сохранение блокируется, если время работы больше планового, годных больше произведённых, плановое время или цикл
  равны нулю, есть выпуск при нулевом времени работы.
- Для нескольких записей суммируются минуты и «идеальное время» выпуска; качество взвешивается идеальным временем,
  поэтому A × P × Q = OEE и для записей с разным циклом. Доля годных по штукам показывается отдельно.
- Период выбирается по **дате смены**. Ночная смена (23:00–07:00) относится к дате своего начала.
- Простои одного оборудования **не могут пересекаться**. Если пересечения есть в старых данных, время считается по
  объединению интервалов — одно и то же время не учитывается дважды.
- Время OEE берётся из записи смены; журнал простоев — отдельный учёт. Несоответствие (простои больше, чем
  «план − работа») показывается в проверке данных.

## Требования

- Python **3.10 или новее** с модулем Tkinter (входит в установщик Python для Windows).
- Сторонние пакеты **не нужны** — используются только стандартная библиотека Python, Tkinter и SQLite.

## Установка и запуск

### Windows

1. Установите Python 3.10+ с <https://www.python.org/downloads/>. В установщике отметьте **Add Python to PATH**.
2. Распакуйте архив в любую папку, например `Документы\PharmaOEE`.
3. Дважды щёлкните `Запустить_PharmaOEE_Windows.bat`.

   Или откройте терминал (PowerShell) в папке программы и выполните:

   ```bash
   py pharmaoee.py
   ```

   Если команда `py` недоступна — `python pharmaoee.py`.

### Linux

```bash
python3 pharmaoee.py
```

или `./Запустить_PharmaOEE_Linux.sh` (при необходимости: `chmod +x Запустить_PharmaOEE_Linux.sh`).

Если Tkinter не установлен, установите системный пакет: Debian/Ubuntu — `sudo apt install python3-tk`,
Fedora — `sudo dnf install python3-tkinter`.

### RED OS

RED OS основана на пакетной базе семейства RHEL/Fedora и использует `dnf`. **Запуск на RED OS не проверялся.**
Ожидаемые шаги (имя пакета Tkinter может отличаться — проверьте `dnf search tkinter`):

```bash
sudo dnf install python3 python3-tkinter
```

```bash
python3 pharmaoee.py --check
```

```bash
python3 pharmaoee.py
```

Команда `--check` проверяет базу и наличие Tkinter без открытия окна — удобно для первой диагностики.

## Где хранятся данные

База данных и служебные файлы хранятся **отдельно от программы**, поэтому обновление или удаление папки с
программой не удаляет данные, а запуск из другого рабочего каталога не создаёт новую пустую базу.

| ОС | Каталог данных |
|---|---|
| Windows | `%LOCALAPPDATA%\PharmaOEE` (обычно `C:\Users\<имя>\AppData\Local\PharmaOEE`) |
| Linux / RED OS | `$XDG_DATA_HOME/pharmaoee` или `~/.local/share/pharmaoee` |
| macOS | `~/Library/Application Support/PharmaOEE` |

В каталоге: `pharmaoee.db` (база), `backups/` (резервные копии), `logs/pharmaoee.log` (журнал работы без
содержимого записей), `settings.json` (настройки). Путь показан в нижней строке окна и в разделе
«Резервные копии».

Другой каталог можно задать параметром или переменной окружения:

```bash
python pharmaoee.py --data-dir D:\PharmaOEE_data
```

`PHARMAOEE_DATA_DIR=/path/to/data python3 pharmaoee.py`

### Переход с версии 8

PharmaOEE v8 хранила `pharmaoee.db` рядом с программой. Если положить этот файл рядом с `pharmaoee.py` v9 до
первого запуска, он будет **скопирован** в каталог данных и обновлён до новой схемы; исходный файл не меняется.
Также базу v8 можно восстановить в любой момент через «Резервные копии → Восстановить из файла…». Перед любой
миграцией создаётся копия в `backups/`.

## Резервное копирование и восстановление

- **Создать копию** — раздел «Резервные копии». Используется backup API SQLite (согласованный снимок), копия
  сначала пишется во временный файл, проверяется (`integrity_check`) и только затем получает итоговое имя.
- **Восстановить** — файл проверяется (формат SQLite, целостность, версия схемы, набор таблиц) → текущая база
  копируется в `backups/` → данные готовятся во временном файле → содержимое заменяется одной операцией. При
  ошибке текущая база остаётся без изменений.
- Перед удалением демо-данных и перед миграцией копия создаётся автоматически.
- При запуске выполняется быстрая проверка целостности. Если база повреждена, программа предложит выбрать копию;
  повреждённый файл не удаляется, а переносится в `backups/`.

## Демонстрационные данные и симулятор

- Генератор создаёт данные только для **демо-линий** (`ДЕМО — …`) и помечает их источником «Демо-данные».
  Одинаковые настройки (период, линии, смены, зерно) всегда дают одинаковые записи; существующие смены и ещё
  не завершённые смены пропускаются, поэтому повторный запуск не создаёт дубликатов. Ограничение — 366 дней.
- Симулятор смены моделирует работу демо-линии (1 шаг = 1 минута смены): остановки, потерю связи, выпуск и брак.
  По завершении сохраняется запись смены с источником «Симулятор». Кнопка «Прервать и отменить» удаляет все
  записи сеанса.
- Ручные сигналы (РАБОТАЕТ / ОСТАНОВКА / ПОТЕРЯ СВЯЗИ) имитируют датчик текущим временем. Остановка открывает
  простой «Не классифицировано» — причину указывает оператор. Потеря связи не считается простоем.
- Удаление демо-данных и данных симулятора **никогда не затрагивает ручной ввод**. Перед удалением создаётся копия.
- В таблицах сгенерированные записи выделены серым, на панели и в CSV выводится предупреждение. Фильтр «Данные →
  Только ручной ввод» исключает их из показателей.

## Экспорт

Раздел «Аналитика и отчёты»: **сводный отчёт**, **записи смен**, **простои** в CSV для Excel (UTF-8 с BOM,
разделитель `;`, десятичная запятая). В начале файла — период, фильтры, время формирования, предупреждение о
демо-данных и пометка об учебном характере отчёта. Значения считаются теми же функциями, что и на экране.
Текст, начинающийся с `=`, `+`, `-`, `@`, экранируется (защита от формул в Excel).

## Тесты

Из папки проекта:

```bash
python -m unittest -v
```

В Windows можно `py -m unittest -v`. Набор из 148 тестов проверяет формулы OEE (включая контрольные примеры,
посчитанные вручную), валидацию ввода, интервалы простоев и переход через полночь, SQLite (CRUD, транзакции,
ограничения, фильтры дат), миграцию базы v8, аналитику периода, генератор демо-данных, резервное копирование и
восстановление (включая повреждённые файлы и сбой во время восстановления), экспорт CSV, обработку событий и
симулятор, пути к данным и запуск, а также интерфейс на реальном Tk (разделы, диалоги, фильтр выбранного дня,
симулятор, экспорт). Все тесты используют временные каталоги и не трогают ваши данные. GUI-тесты пропускаются,
если нет графического окружения.

## Структура проекта

```
pharmaoee.py                  точка запуска
pharmaoee_app/
  config.py                   пути к данным, настройки, журнал, смены, причины по умолчанию
  oee.py                      формулы OEE (только расчёт, без обрезки до 100%)
  validation.py               разбор и проверка ввода, расписание смен
  intervals.py                интервалы простоев: пересечения без двойного учёта
  db.py                       SQLite: схема, миграции, все SQL-запросы, журнал изменений
  analytics.py                показатели за период, разрезы, проверки данных
  demo.py                     генератор демо-данных
  sources.py                  интерфейс источников данных, обработка событий, симулятор смены
  backup.py                   резервное копирование и восстановление
  export.py                   экспорт CSV
  main.py                     запуск, миграция, восстановление повреждённой базы, режим --check
  ui/                         интерфейс Tkinter: тема, виджеты, графики, диалоги, разделы, главное окно
tests/                        автоматические тесты (unittest)
docs/ARCHITECTURE.md          архитектура, схема базы, правила расчёта
```

## Производительность

Замер на Windows 11, Python 3.15.0 (один компьютер, значения ориентировочные): генерация года демо-данных
(3294 смены, 7591 простой) — 0,8 с; загрузка и расчёт показателей за год — 0,09 с; обновление каждого раздела
на годе данных — до 0,11 с (первое построение главной панели — 0,65 с).

## Известные ограничения

- Нет пользователей, ролей, электронной подписи и защищённого от изменения аудиторского следа; журнал изменений —
  обычная таблица базы данных.
- Нет подключения к реальному оборудованию; события только от симулятора и кнопок.
- Время хранится как местное время без часового пояса; интервал, пересекающий переход на летнее время, может
  отличаться на 1 час (в России переход не применяется).
- Расписание смен (07:00, 15:00, 23:00 по 8 ч) фиксировано в `config.py` и используется для подсказок и демо-данных.
- Окно не адаптировано под масштаб Windows выше 100% (система масштабирует его целиком, текст может быть менее
  чётким).
- Тёмная тема не реализована.
- Работа на Linux, RED OS и macOS не проверена.
